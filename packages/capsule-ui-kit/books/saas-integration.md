# SaaS shell integration

The production v2 entry imports `SaasShellGrid.vue`. The build enables Vue Options API, and the consumer registers its labels, groups, icons, capsule components and placement with the shared AppShell. The kit owns navigation, topbar, search palette, theme toggle, workspace settings, status and the top-bar terminal toggle. The bottom orchestrator drawer, the status-bar Terminal shortcut and the terminal capsule are retired; the terminal lives in the right-side overlay panel. DockWorkspace remains the sole layout owner.

OpenVue receives the per-document style nonce generated by the consuming application. The host supplies a meta element whose name ends in `-style-nonce` (for example, `capsule-style-nonce`); this also supports existing consumer-specific prefixes without encoding a product name in the kit. Missing nonce refuses installation. Aura remains an adapter over the kit token authority. The admitted declarations do not specify `darkModeSelector`: AUSENTE — no inventar. The toggle changes kit scheme tokens; no unproven vendor selector is configured.

The installed xterm sources bypass `documentOverride` in browser-service construction and row-factory construction. `capsule-ui-kit/xterm-csp` exports a build plugin that corrects those exact vendor anchors and refuses drift. The declared document override then supplies nonce-bearing style elements and applies generated row declarations through CSSOM. No installed vendor file, global document method or DOM prototype is changed. Consumers using the side terminal panel must install this build plugin and provide the document nonce.

SideTerminalPanel receives a closed facade from its consumer. The first open starts the user's real login shell; the "+" menu offers System shell first, then host-supplied provider entries launched inside the login shell, plus a free-command entry. It requires explicit opt-in when main advertises player mode, and uses real xterm/FitAddon with TerminalSessionTabs tabs. All session views stay mounted; collapsing the panel preserves sessions, and an exited tab stays dimmed and readable until closed. Unsupported attach/reconnect remains disabled. CLI/model readiness metadata is AUSENTE — no inventar; running PTYs retain unknown activity until an authoritative exit rather than deriving readiness from output.

`app/shell/test/tp7-B-live.test.js` builds the production entry in a temporary app and verifies main nonce delivery, no document overflow, absence of the retired terminal capsule and drawer anchors, theme, palette, renderer semantic snapshots and strict absence of CSP events or renderer errors. The test uses the installed Electron, a freshly built native image and an isolated Xvfb display. This is production-source integration evidence; packaged distribution certification remains the conductor's gate.

`app/shell/test/tp7-B-battery.test.js` replays the existing v2 battery oracles. Refresh mode requires independent captures to match and preserves all non-hash assertions before changing presentation pins. Changed fields and their previous values are recorded in the v2 fixture justification document. The full strict suite is reserved for the conductor.

This integration judgment is limited to the supplied design corpus, installed declarations, granted source surfaces and recorded targeted host evidence.
